## 目录工具与 Agent 输入

### 1. “resolve_workspace_file 是什么意思呢？”

这是项目自己写的函数：把工作区与相对路径组合起来，解析真实位置，并检查目标是否仍在工作区内。它不读取文件内容，也不判断目标一定是普通文件；名字里有 file，返回的 Path 仍可能指向目录，因此列目录前还需 is_dir() 检查。

工作区为 /project 时，logs 对应 /project/logs；../outside 会越界；软链接的最终目标在工作区外也会被拒绝。读取函数和写入函数可以在此基础上执行各自的类型与存在性检查。

拟补位置：第 3 课的工具执行边界、目录工具配套说明。实现依据：[路径解析函数](../practice/workspace-agent/agent.py)。

### 2. “execute_read 是什么意思，一个特定的函数吗？”

它是本项目定义的读取请求处理函数，不是 Python 自带功能。目录练习的 execute_tool() 收到读取请求后调用它；它检查工具名、参数与允许名单，再调用 read_file() 真正读取，最后返回 JSON 格式的工具结果。

拟补位置：第 2～3 课，用一条调用路径区分模型提出的工具名与程序内部函数名。实现依据：[execute_tool](../practice/lesson-03/directory/tools.py)、[execute_read](../practice/lesson-03/demo.py)。

### 3. “允许的文件名在哪里存储？怎么动态增加删除？”

当前教学实现把路径写在 demo.py 的 ALLOWED_FILES 集合中，没有单独配置文件。运行中 add／discard 可以改变集合，但模型看到的 TOOLS 参数枚举是在初始化时由 sorted(ALLOWED_FILES) 生成的列表，不会自动跟着变化。动态修改要同时更新执行规则和工具说明；要跨重启保留设置，才另行选择配置存储与加载方式。

允许名单由应用管理，不由模型在参数里自行批准。列目录看到一个文件名，也不自动获得读取权限。

拟补位置：第 3 课工具说明与执行检查、第 7 课工具策略。只说明当前实现，不把动态配置说成已经完成的功能。

### 4. “允许了 10000 个文件，也要把文件名都发给大模型吗？”

不必。允许访问哪些资源是程序的执行规则，本次模型需要什么材料是上下文选择。大名单不宜原样放进工具 Schema 的 enum；可以让模型提供相对路径，由执行器继续检查权限，再用检索和分页帮助发现相关材料。

分页按顺序返回一批条目，检索按问题寻找相关内容。分页可以缩短返回结果，但当前目录实现仍会扫描并排序整个目录，不能声称扫描成本也消失了。

拟补位置：第 5 课的上下文选择，以及后续检索主题。

### 5. Python 细节为什么容易打断主线？

本轮实际卡点包括 return 与 raise 的区别、返回列表与返回字典的区别，以及切片的起止位置。最短提示分别是：return 交回一个普通结果，raise 抛出异常；返回结构要符合调用方约定；切片包含起点、不包含终点。

这些问题需要回答，但不再扩展成连续的 Python 语法关卡。当前学习安排是：通用实现与测试脚手架由助手完成，业务规则结合实际需求解释，学习者重点理解 Agent 控制流程。

## RAG 与检索

### 6. “RAG 的原理是什么，前提是需要向量化吗？”

RAG 把检索与生成连接起来：先找相关资料，再把问题和取得的资料交给模型回答。检索可以使用关键词、语义向量或两者结合；向量化不是通用 RAG 的必要前提。原始 RAG 论文采用了具体的稠密检索方案，不代表所有后续系统都必须照搬。[1]

这也不等于把公司资料重新训练进回答模型。常见实现是在每次请求中提供所需资料。固定程序可以安排整个流程；Agent 也可以根据结果决定继续检索或结束。

拟补位置：后续检索主题的开头。当前不视为已新增或发布的第 11 课。

### 7. “向量的原理又是什么？”

向量是一组有顺序的数字；Embedding 将文本转换成可用于比较的向量表示。用于语义检索的模型通过训练，使相关表达的表示更相似；随意分配数字不能得到同样效果。具体某一维通常不能直接解释成一个人工命名的业务指标。[2][3]

向量相似只是候选线索，不保证产品、版本或条款适用。家庭套餐与个人套餐都在讨论账号数量，可能很相似，仍要核对具体对象。

### 8. 只保留向量，为什么还不能回答？

检索返回相似向量或记录 ID 后，还需要取得对应原文。可以把原文与向量放在同一条记录，也可以保存片段 ID，由它查询另一个文档存储。[1]

```text
相似向量对应片段 chunk_A
-> 用 chunk_A 找回“家庭套餐最多支持 6 个账号”
-> 把问题和这段原文交给回答模型
```

向量不是原文的无损压缩包。若既没保留原文，也没保留可靠的取回关联，回答模型就缺少检索依据。文档更新或片段替换后，关联也需要保持正确。

### 9. “倒排索引什么意思？”

先有三段示例资料：

| 文档 | 原文 |
| --- | --- |
| A | 家庭套餐最多支持 6 个账号。 |
| B | 个人套餐最多支持 3 个账号。 |
| C | 家庭套餐的开通流程。 |

从文档看它包含什么词，方向是“文档 -> 词”。把方向反过来，记录“词 -> 出现在哪些文档”，就是倒排索引。下面只展示选出的几个词，省略其他词及位置信息：[4]

```text
家庭套餐 -> A、C
个人套餐 -> B
账号     -> A、B
开通     -> C
```

查询“家庭套餐 账号”，先查到 A、C，再查到 A、B；在这个简化的同时匹配例子中，两份清单都有 A，因此先取回 A 的原文。实际全文搜索还可以使用词频、词的位置等信息排序。

索引提前保存了这些关系，查询时可以直接找相应清单，而不必每次从头读完所有文档。不需要先调用 Embedding 模型。索引命中后，仍需取回原文才能给回答模型提供完整依据。

单纯按字面匹配时，用户说“全家一起用”，资料却只写“家庭套餐”，就可能匹配不上。分词负责切开文字，本身不等于理解这两种说法的关联。

### 10. 关键词搜不到，就必须用向量吗？

不一定。对于已知的业务说法，可以维护短语映射，将“全家一起用”扩展成包含“家庭套餐”的查询，再查倒排索引。这叫查询扩展，不需要向量。

```text
用户问“全家一起用，能有几个账号？”
-> 查询扩展：补入“家庭套餐”
-> 关键词检索：家庭套餐、账号
-> 取回 A 的原文
```

用户说法很多、难以逐一维护时，向量检索可以帮助寻找意思相关的候选，也可以与关键词检索结合。它仍可能找错套餐，不能省掉原文核对。这里的关键是“表达不同”，不能只归因为分词，也不能直接推出“必须用向量”。

### 11. “给查询补上家庭套餐，怎么实现？不需要向量吗？”

最简单的实现就是人工写一条规则。下面只演示生成检索词，不是完整搜索程序：

```python
question = "全家一起用，能有几个账号？"
search_terms = [question]

if "全家一起用" in question:
    search_terms.append("家庭套餐")

assert search_terms == [question, "家庭套餐"]
```

`in` 检查问题里是否包含这串文字；`append` 将“家庭套餐”加入列表。程序没有自动理解两种说法，是写规则的人告诉了它这个业务关联。接下来由搜索程序将新增短语作为候选查询词，而不是要求文档包含整句原问题。这既不需要向量，也不需要调用大模型。

规则多了，可以存成“用户说法 -> 检索词”的配置表。代价是要维护：用户换成“我和爸妈都想用”，这条精确短语规则就不会触发；“不想全家一起用”却也会触发。因此它只适合补充检索候选，不能据此直接替用户选套餐。

错误码 E1042 这类精确标识适合优先精确匹配，避免把相似的 E1043 混进来；索引也要保留完整标识。向量检索更适合补充寻找表达不同但意思相关的资料。

### 12. 过期资料是否应该一律排除？

不应该。用户问“现在”，查询当前生效的规则；问“2023 年”，查询那时生效的规则。资料今天已失效，不代表不能回答历史问题。

元数据可以记录产品、生效日期、失效日期。程序按用户问题对应的时间过滤，再在适用资料中检索相关内容。以包含生效时刻、不包含失效时刻的约定为例，目标时刻必须不早于生效时刻，且早于失效时刻；没有失效日期时，需要明确其是否表示持续有效。过滤条件取决于问题，不能永远写死为“当前有效”。

还要区分发布日期与生效日期。2023 年发布的资料不一定覆盖整个 2023 年；如果年中规则变过，应分时间段回答，或在需要单一结果时询问具体日期。上述判断依赖可靠的版本元数据和可取回的历史原文，向量相似度不能替代这些条件。

### 13. 控制操作的是 Harness，为什么又说模型选择下一步？

这里混用了“提出动作”和“执行控制”。模型可以根据已看到的结果提出下一步工具调用；Harness 检查参数、权限、审批和预算，决定是否执行，并把结果送回模型。模型的选择不是执行授权。

固定 Workflow 也有外部程序调度，可以复用同一套 Harness 能力。不能用“有没有 Harness”区分 Workflow 与 Agent，也不能用“有没有调用模型”区分。

在本书的教学区分中：如果程序预定“检索一次，再让模型总结”，模型只负责组织回答，这是固定 Workflow；如果允许模型根据检索结果提出换关键词、换工具或询问用户等下一步请求，再由 Harness 约束并执行，就包含 Agent 式决策。实际系统可以把两者组合，不必强行二选一。

```text
模型：现有资料不够，申请改查退款政策。
Harness：检查调用是否合法、是否有权限、是否超出预算。
工具：通过检查后，实际检索。
Harness：把结果送回模型，或反馈拒绝执行的原因。
```

前一轮“下一步由模型选择”的说法省略了执行控制边界，应修正为“模型提出下一步，Harness 守住执行规则”。

### 14. Agent 循环和 ReAct 是什么关系？

ReAct 将推理与行动交替组织：模型判断下一步，提出动作，通过外部执行取得观察结果，再根据结果调整后续行动。[5] 在本书的工具调用例子中，模型提出检索请求，Harness 检查并执行工具，工具结果进入下一次模型请求；模型再决定继续查、询问用户或回答。

因此前述程序 B 具有 ReAct 式的反馈循环，但不能仅凭有工具循环就断言它完整实现了原论文的提示方式。ReAct 是一种组织推理与行动的方法，不是所有 Agent 的唯一实现，也不替代 Harness 的权限、预算与执行控制。应用不必展示模型的内部推理全文，仍可观察工具请求、返回结果和后续动作。

### 15. 文档块怎么存？“套餐”就是一个倒排索引吗？

在退款规则与账号规则之间切开合理，因为两段讨论不同主题；退款规则及其例外条件应留在一起。两段都出现“套餐”，不代表应该按这个词切分。分块处理内容边界，分词提取检索用词，是两个动作。块太小可能丢条件，太大又会带入无关内容；短手册也可以直接提供全文，不必强行分块。

切完先保存每块的编号、标题和原文，例如数据库中每块一行：

| 块编号 | 标题 | 原文 |
| --- | --- | --- |
| C1 | 退款规则 | 购买后 7 天内可退款，但已经使用的套餐除外。 |
| C2 | 账号规则 | 家庭套餐最多支持 6 个账号。 |

再根据文字建立检索索引。假设分词提取了“退款”“账号”“套餐”，下面是索引中选出的三项：

```text
退款 -> C1
账号 -> C2
套餐 -> C1、C2
```

“套餐”是索引里的一个词项；“套餐 -> C1、C2”是一条映射，不是整个倒排索引。搜索“退款”时先由索引找到 C1，再用 C1 取回保存的原文，交给模型。单独的“套餐”会命中两块，因为它不能区分退款与账号规则。

文本块可以存在 SQLite 等数据库中，索引由检索组件维护；逻辑上分开讲，不要求物理上用两套数据库。生产记录还需保留原文来源、顺序及适用的版本、权限等元数据。这里的表格只展示最小存储关系，不代表完整实现。

### 16. 原文更新或删除后，索引会怎样？

把 C1 的退款期限从 7 天改为 3 天，需要用新的向量生成输入更新对应向量。旧向量不一定无法命中 C1，而是检索依据与当前原文不一致，可能影响召回和排序。如果仍命中 C1，并取回最新原文，模型看到的可以是正确的 3 天；若返回的原文副本也过期，则可能把旧规则送给模型。

只更新受影响的块即可。C2 的生成输入、Embedding 模型与生成配置均未改变时，可以复用原向量；若分块边界或加入向量输入的标题等发生变化，也需要重新判断更新范围。

在索引只保存编号、原文另存的例子中，删除 C1 原文但不清理索引，会出现“命中 C1，取不到原文”。程序不能把这次命中当作回答证据，应跳过该候选、记录异常并清理失效索引。若索引或缓存还保存原文副本，也要同步删除或使其失效，不能继续返回已撤下的资料。更新、删除都需要维护原文与索引的一致性。

### 17. 对词还是对原文向量化？向量检索也查倒排索引吗？

前面交替介绍两种检索，容易被误听成一条串行流程。对本例应明确分开：关键词检索根据词项查倒排索引；稠密向量检索根据向量相似度查向量索引，不需要先经过前述“词 -> 文本块编号”的倒排索引。

倒排索引与向量索引支持两种不同的查找方式：

| 检索方式 | 拿什么查 | 查哪种索引 | 示例 |
| --- | --- | --- | --- |
| 关键词检索 | 查询中的词或编号 | 倒排索引 | 用 E1042 找包含该错误码的资料 |
| 向量检索 | 问题生成的向量 | 向量索引 | 用“我和爸妈都想用”寻找意思相关的套餐资料 |

两路最终都要取得对应原文，才能为回答提供依据。这里比较的是常见的词项检索与稠密向量检索，不是在列举所有搜索引擎内部的索引实现。

常见的文本块向量检索实现，是将长文档分成保留完整意思的块，把每块的文字送入 Embedding 模型，得到对应向量。不是把每个中文词单独向量化后分别当作本例的检索记录，也不是必须把整本长手册压成一个向量。模型内部会把输入编码为 token，这与应用层中文关键词分词、文档分块不是同一个步骤。

```text
关键词路线：原文块 -> 分词建倒排索引；查询词 -> 倒排索引 -> 块编号 -> 原文
向量路线：原文块 -> Embedding 建向量索引；问题 -> 查询向量 -> 向量索引 -> 对应原文块
```

向量与原文保持关联，向量化不会把原文替换掉。可以在同一条记录保存块编号、原文、向量，也可以分开存储。检索接口若已返回原文，就无需额外查一次数据库；若只返回编号，则按编号取回原文。用户说“命中的是原文”在使用结果上可以成立，但检索过程比较的是向量，最终拿到的是它对应的原文。

查询向量与文档向量应由配套的 Embedding 编码方式产生，处于可比较的空间。拿到原文后，还要把问题和适用的证据放进回答模型的输入，才完成 RAG 的生成部分。两种检索可以合用，但不是“先向量化，再用向量查关键词倒排索引”的固定流水线。

### 18. 两种检索一起用，就是混合搜索吗？

是的。在这里，让同一次查询结合关键词与向量两路的结果，叫混合检索，也叫混合搜索（Hybrid Search）。关键是融合结果：仅仅建好两种索引，但一次查询只走其中一路，还不算这里说的混合检索。[6]

例如用户问“E1042，为什么登录不上”：关键词路线帮助找准 E1042，向量路线补充寻找描述登录故障的相关资料。两路的候选合并后，按文本块编号去重，融合排名，再选取适量原文交给模型。

```text
同一个问题
  +-> 关键词检索 -> 倒排索引 -> 候选列表
  +-> 向量检索   -> 向量索引 -> 候选列表
                               |
                     合并、去重、融合排名
                               |
                      选取原文，交给模型
```

同一块被两路找到，不需要重复塞进上下文。两路分数的量纲可能不同，也不宜直接相加；可以按排名融合，例如 RRF，具体算法留到需要实现时再展开。融合后的资料仍要满足用户权限、产品和时间等条件。混合检索不是“只有两路都命中才保留”的简单取交集，也不能保证排第一的就是正确答案。

## 已观察到的学习证据

学习者原话：

> 肯定不知道啊，模型只能获取发送给它的信息。

> 缺少向量索引到原文的能力啊

> 搜索不到，因为没有全家一起用的分词。这时候需要用向量。

教师反馈：第一句在工具结果进入下一次请求的语境下正确；第二句正确指出向量记录与原文之间的取回关联。学习者也正确选择先检查检索为何取错套餐资料。第三句正确识别字面匹配可能漏检，但把表达差异归因为分词，并把向量视为唯一解决办法；已补充查询扩展示例，尚待迁移检查，不标记为已掌握。

对错误码 E1042 的检索选择，学习者回答：

> 优先字符串匹配查询啊

教师反馈：选择正确；已补充精确标识不宜混淆相似编号的原因。学习者追问查询扩展如何实现，已给出字符串判断示例，不能据此认定已理解其泛化边界。

对换一种表达能否触发固定规则，学习者回答：

> 不能补上啊，你这是字符串匹配啊，局限性太大了

教师反馈：正确指出精确短语规则的覆盖边界。随后能提出将少量候选都交给模型，或用关键词进一步筛选；已提醒避免按原问题字面再次过滤而丢失语义相关资料。

对查历史规则，学习者回答：

> 会查询A。  不是当前有效，是过去2023年的有效，还是通过元数据判断

教师反馈：正确将有效性与问题中的时间关联，而非只保留当前版本。已补充年内规则变化与发布日期不等于生效日期的边界；不能据此认定掌握了所有时间过滤实现。

后续回答中，学习者能指出找不到资料就说明找不到、不能用另一家公司的政策回答，并强调无权限不应读取。教师补充：未检索到不等于政策不存在；资料适用性与访问权限要分开；权限规则需要程序实际执行。

对 Workflow 与 Agent 的区分，学习者指出：

> 模型没有harness啊，控制操作的是harness

教师反馈：正确强调 Harness 的执行控制职责；前一轮教师用“模型选择下一步”省略了执行约束，容易误导。已补充分工及固定 Workflow 同样需要外部程序调度，不把当前疑问当作已掌握分类。

对达到调用上限，学习者正确指出应退出循环；教师补充停止不等于成功，循环次数也未必等于工具调用次数。学习者一度把固定检索后总结判断为 Agent；拆开具体执行步骤后，回答：

> 不能，直接就结束了。
>
> B更像是 agent,有 React的感觉

教师反馈：已能识别固定流程无法自行再次检索，并将根据观察结果选择后续动作与 ReAct 联系起来；已说明拼写为 ReAct，以及方法与执行控制的区别。

学习者正确指出工具结果必须进入模型输入；只写日志而未发送，模型看不到。对分块拆散退款条件，能指出条件没有搜全；对整本手册全部送入模型，能指出上下文容量限制，教师补充短文档可以直接提供全文。

对切分与索引的关系，学习者说：

> 规则一和规则二切开，  两个都有套餐，可以按套餐切开，但是不知道如何存储，套餐是一个倒排索引？

教师反馈：切在主题边界正确；“按套餐切开”仍混淆分块与检索用词。已给出文本块表和词到块编号的映射，说明“套餐”是词项而非整个倒排索引，尚待独立取回原文的流程检查。

对索引命中后怎么取得内容，学习者回答：

> 要根据倒排索引，回到数据库，反查那一行的原文啊

教师反馈：正确串起词项、块编号与原文取回；索引已返回编号后，取原文使用该编号即可。对更新向量，学习者指出应随内容更新，但认为旧向量“无法匹配”；已纠正为可能仍命中，只是检索依据过期。学习者正确判断未受影响的 C2 不必更新，教师补充生成输入和模型配置不变的前提。

对原文删除但索引保留，学习者回答：

> 会搜到c1,但是显示原文不存下

教师反馈：在本例分开存储的前提下正确识别命中后取回失败；已补充失效候选不能作为证据，以及索引、缓存中原文副本也要处理。

学习者尝试串联流程时写道：

> 进入 RAG系统前，需要分词，然后向量化
>
> 1. 先对搜索内容向量化
> 2. 根据向量命中倒排索引
> 3. 根据倒排索引取出对应的原文

并追问：

> 对了，是对分词向量话，还是对所有原文都向量化啊？如果原文向量化了，搜索命中的就是原文了，而不是倒排索引了吧

教师反馈：更新、删除时维护对应索引的方向正确，查询向量化适用于向量检索；但将分词与分块、倒排索引与向量索引串成了一条流程，还漏了原文进入回答模型的步骤。已补充每块文字生成向量、向量与原文并存，以及接口可直接返回原文的说明。此处显示单点判断正确尚不等于能独立串联全流程，应先巩固而非引入新术语。
