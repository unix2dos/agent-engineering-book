## 读者与贯穿项目

面向会基本编程、初学 Agent 的读者。先做一个 Python 服务的只读排查助手：接过故障请求，查日志和源码，给出有证据的解释；后续再扩展到受限修复、恢复和验收。以读者能做出、改动并讲清一次任务为目标，不把运行示例等同于掌握原理。

订单案例负责减少重复熟悉背景的成本。其他案例只在更能说明机制时使用，例如用模拟通知说明“重复执行”的后果；不接真实支付或生产环境。第 0 课仍是独立选读的历史地图。

## 每课只增加一项主要能力

下表是拟写的递进，不是已经完成的功能清单。原稿中有效的代码、事实和案例继续保留，未验证的新场景不写成实测。

| 课次／主题 | 承接什么，出现什么新问题 | 本课增加什么，读后凭什么说清楚 |
| --- | --- | --- |
| 1 Agent 基础 | 接到“查清接口为什么报错”的需求 | 比较一次模型调用、固定流程和模型自主选路；说清哪些判断值得交给模型 |
| 2 Agent Runtime | 已决定让模型选择排查动作，却一直等不到日志 | 沿一次读取定位 Model、Harness、Tool、Environment 的职责；知道先查哪一层 |
| 3 Tool Calling Loop | 职责已明确，怎样把“申请、执行、回传”接起来？ | 用关键代码跑通读日志、读源码、回答；说明调用编号、消息累积和停止条件 |
| 4 Session 持久化 | 排查中断，重新打开以后怎么接着查？ | 对照历史记录与恢复快照，分清 Session、Transcript、Checkpoint、Memory；JSON／JSONL 随存取动作解释 |
| 5 Context Engineering | 记录保存了，但历史和日志太长，不能每次全部递过去 | 展示完整材料与本轮输入的差别；解释裁剪、压缩及保留工具消息关系的理由 |
| 6 Tool Reliability | 从只读扩展到受限写入：修改已经发生，成功回执却没存上 | 核对执行账本，区分已知失败与结果不明；演示补回执和防重复执行，按并发需求再引入事务／唯一约束 |
| 7 Agent Sandbox | 允许改项目文件，是否也允许读取项目外材料？ | 用实际拒绝结果区分工具策略、批准、系统权限和沙盒；不能靠“请勿越界”代替限制 |
| 8 Agent Tracing | 任务等了很久，每个组件却都说自己成功 | 把模型、工具与等待时间接到同一次运行；说明 Trace／Span 和诊断价值，不把全套 Tracing 当成最小 Agent 的前置条件 |
| 9 Agent Evaluation | 换了模型或提示词，怎样判断诊断、修复是否变好？ | 固定输入和验收条件，对比产物、运行结果与成本；用已有坏例说明回归门禁，不让评分器兼任权限边界 |
| 10 Agent Orchestration | 修复、验收、返工与等待怎样可靠衔接？ | 用外层固定流程控制内层 Agent；再按真实需要引出路由、交接、并行与共享预算，框架对照放在对应动作旁 |

## 三处需要先理顺的衔接

- **第 1～3 课不重播同一个开场。** 第 1 课定需求和选择理由；第 2 课直接接一次读取卡住；第 3 课开始接线、运行。500 样章的材料按这些职责重新分配，不整篇塞进第 3 课后再接旧正文。
- **写入前已有基本限制。** 第 3 课只开放有限读取，第 6 课只在隔离的教学工作区内演示获准写入。第 7 课解释并强化边界，不意味着此前可以无约束执行。第 4 课先讲存取与恢复；SQLite 的查询、事务细节放回第 6 课或已有专项练习，保留就近提示。
- **观测、评估、编排各自交付不同结果。** 第 8 课解释一次运行，第 9 课比较不同版本，第 10 课控制接下来做什么。它们可共享证据，不要求先建设完整观测平台。

## 写法与交付

用户已确认保持这套风格：标题与关键术语保持专业，并保留有层次的小标题、必要的对照表和流程图。案例负责引入问题，节内用通俗语言解释机制，不能把全章写成没有知识落点的连续叙述。术语首次出现时解释清楚，之后使用同一名称，不用比喻替换正式概念。

`ljg-writes` 用于组织章节与小节的递进，`ljg-plain` 用于解释难懂的段落；本书明确保留 Markdown 章节结构，不采用其“全文无子标题”的文章格式。代码出现在需要解释机制的位置，必要限制紧跟相关结论。每课应有能在书内看懂的过程或结果，参考链接供追溯，配置和完整脚手架放配套材料；不靠统一字数、笑话或插图配额制造一致性。

按第 1、2、3 课顺序提供整章候选和修改对比，每篇确认后才应用。三篇连续验读后再扩大到第 4～7 课，然后处理第 8～10 课；导读和历史篇最后校准。应用前核验代码与引用，提交、发布另行确认。遇到范围改变或材料不足，先讨论，不靠编造结果补齐故事。
