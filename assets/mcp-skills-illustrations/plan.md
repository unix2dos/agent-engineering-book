## 01：读方法，提申请，等结果（优先）

- 插入位置：文章解释 Skill、模型、Harness、MCP 的职责之后，复用本次截图中的认知位置。
- 图的主题：同一次套餐查询中，四者怎样协作。
- 核心意思：Skill 提供方法，模型提出动作；Harness 检查并安排执行；MCP 连接工具服务；真实结果经宿主返回模型。
- 结构类型：系统局部与单个往返动作，不画完整技术架构。
- 原创隐喻：一个带受控气送信筒的古怪查询工位。小黑坐在工位左侧，翻着薄薄的 Skill 手册，将查询纸条递到受控投递口；投递口内是 Harness 检查机构。通过检查的纸条沿标有 MCP 的管道到达右侧套餐资料抽屉，结果纸条沿回程回到检查机构，再交还小黑。
- 小黑动作：一只手扶住翻开的手册，另一只手递交查询申请；空表情认真等待回执。不能让它操纵检查闸门或越过通道直接伸进资料抽屉。
- 元素：小黑、手册、带投递口的工位、MCP 双向通信管道、工具服务抽屉、少量往返纸条。将工位与管道画成同一个主要装置，避免散成一排卡片。
- 建议标注（最多 8 处）：`Skill 方法`、`模型`、`Harness 检查`、`MCP 通信`、`工具服务`、`查询申请`、`6 个账号`。
- 正文图注：模型提出查询，Harness 检查后通过 MCP 请求工具执行；结果回到模型，才能继续回答。Skill 提供方法，不代替权限检查。
- 技术检查：MCP 是通道而非执行者；资料由工具读取；Skill 不连接闸门的授权开关；回程必须回到小黑；不能把模型与 Harness 画成同一个角色。管道只比喻消息交换，不暗示 MCP 必须通过网络，也不把整幅图称为真实部署图。
- 暂缓内容：Host 边界、MCP Client 内部结构、JSON Schema、协议版本与通信报文。这张图不承担所有名词的解释。
- 拟保存路径：`assets/mcp-skills-illustrations/01-guidance-call-result.png`。

## 02：同一个查询函数，两种接法（可选）

- 插入位置：“没有 MCP，之前的 Agent 为什么也能工作”这一段之后。
- 图的主题：MCP 是可选接入方式，不是 Agent 必须增加的一层。
- 核心意思：本地直接调用与 MCP 接入都能使用查询能力；MCP 多解决统一发现、调用和结果交换的问题。
- 结构类型：上下两幅短分镜，平行对照，不画升级阶梯。
- 原创隐喻：上下各一张剖开的办公桌。上格，小黑按工位上的查询按钮，受控机构直接操作同桌的查询抽屉；下格，同一动作通过标准接头连到独立工具柜。两格都在工位处保留检查机构，也都交回写有“6”的回执。
- 小黑动作：实际提交同一张查询纸条，接住回执，不能只站在图旁。
- 元素：重复的同一角色、查询纸条、检查机构；上格近处抽屉，下格独立柜与接头。下格不出现云朵，避免暗示 MCP 必须远程运行。
- 建议标注：`直接调用`、`MCP 接入`、`Harness`、`get_plan`、`6`。用布局表达对应关系，必要解释留在图注。
- 正文图注：原来的函数调用路径仍然成立。需要统一连接独立工具服务时，可以采用 MCP；检查权限的职责不会随接法消失。
- 技术检查：不表示 MCP 比直接调用必然更快、更聪明或更安全；不画成只能二选一的系统，两种接法可在同一 Host 内共存。
- 拟保存路径：`assets/mcp-skills-illustrations/02-direct-or-mcp.png`。

## 生成与入文顺序

先生成并审查 01。能让读者区分“方法、申请、控制、通信”就足够，不为凑数量添加第二张。02 只在文章仍容易让读者误以为“必须使用 MCP”时生成。

生成后核对中文、往返方向和角色职责。小黑仅作装饰、图像像 PPT、概念标签超过 8 处或主图塞入完整 Host/Client/Server 架构，都应返工。原始生成文件保留；正文采用确认后的图片，并附图注与替代文本，不能让理解完全依赖图片。
