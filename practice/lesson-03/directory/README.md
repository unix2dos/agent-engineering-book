# 受限目录工具：观察一次 Agent 调用

目录查看与分页已经实现。接下来重点看模型怎样提出请求、Harness 怎样执行、结果怎样进入下一次模型请求；Python 筛选和切片作为配套代码，不再单独设语法关卡。

## 先看一遍运行过程

在仓库根目录运行：

```bash
python -B practice/lesson-03/directory/check.py --demo
```

演示使用临时目录，每页一个文件名：

```text
模型申请 list_files(path=".", limit=1)
工具返回 order_service.py，next_offset=1

模型申请 list_files(path=".", offset=1, limit=1)
工具返回 server.log，next_offset=null

模型申请 read_file(path="server.log")
工具返回日志内容

模型给出最终回答
```

目录与文件读取真实发生；模型回复是预设剧本，用于观察消息与调用顺序，不代表真实模型已经能自己规划路径。

## 三处 Agent 逻辑

| 位置 | 职责 |
| --- | --- |
| [tools.py 的 TOOLS](tools.py) | 告诉模型工具名称、用途和参数；模型可以申请哪个动作 |
| 同文件的 execute_tool() | 分发请求、检查字段、传入参数、将结果转为 JSON 字符串 |
| 已有的 [run_agent_loop()](../../workspace-agent/agent.py) | 把结果作为 role=tool 消息回传，保留 tool_call_id，再请求模型 |

`next_offset` 只是下一页的位置，不会让工具自动读完所有页。模型在下一次请求中可以继续列目录、读取已有证据，或结束。上面的示例有四次模型请求，其中三次提出工具调用，最后一次回答用户。

目录里看见文件名，不等于取得读取权限。当前 `read_file` 仍只允许根目录的 `server.log` 和 `order_service.py`。本次分页限制的是目录工具的结果大小，没有改动读取允许列表或其 Schema 枚举。

## 已完成的工具约定

- `path` 是工作区内的相对目录，Python 函数默认取 `"."`；模型调用需提供该字段。
- `offset` 是排序后文件名列表的起始位置，按条目计数，默认 0；`limit` 是每页条数，取 1～100 的整数，默认 20。布尔值、字符串和小数都不能冒充整数。
- 只列本层普通文件，先排序再分页；跳过目录条目和所有软链接，不读取内容。
- 返回 `path`、当前页的 `files`、以及 `next_offset`；到末尾返回 null（Python 中为 None）。空目录或超过末尾也返回空清单和 null。
- 越界、绝对路径、指向外部的目录软链接、非目录与非法参数会被拒绝。参数错误会作为 Tool Result 返回，给模型修正请求的机会。
- 文件系统读取失败保留为受控错误，不把绝对路径直接放进错误回执。

每次仍扫描并排序整个目录；分页减少返回量，不提供目录快照。分页期间若文件发生增删，可能重复或漏项。本例用于受控、稳定的教学目录，不等于完整操作系统 Sandbox。

## 验证与复盘

先观察预设流程以后，可以用现有模型连接做一次真实排查：

```bash
python -B practice/lesson-03/directory/run.py --self-check
python -B practice/lesson-03/directory/run.py --live
```

`--live` 读取环境变量 `OPENAI_API_KEY`、`OPENAI_MODEL` 和可选的 `OPENAI_BASE_URL`，可能产生费用。需要会话编号请求头的 Provider 可加 `--session-header 请求头名称`。每次最多 4 次模型请求、每次输出最多 2048 Token；SDK 超时 30 秒、自动重试为 0。

它会在临时工作区复现订单接口的 500，让真实模型查看目录、读取日志与源码并给出建议。工作区只放教学材料；会话和报告保存在目录外，结束后保留供复盘。它不修改业务代码，不自动重试失败任务，也不把正常结束等同于诊断正确。本次已完成的观察见[实测复盘](实测复盘.md)。

```bash
python -B practice/lesson-03/directory/check.py
```

检查覆盖多页、最后一页、空目录、默认值、数量上限、非法参数、越界、软链接，以及带分页参数的完整工具循环。还会验证错误参数能回传后被修正，输入文件没有被改写。无需 API Key。

`--wiring` 仅检查接线，现在也使用已经实现的真实目录工具，不再替换目录结果。

复盘时关注三个判断：为什么目录结果要进入消息；为什么执行器还要检查模型参数；看见文件名为什么不代表能读取。随后再把这些控制规则带到实际排查需求中。
