## 这次能讲清的 Agent 原理

模型提出工具名和参数，Harness 校验并执行，再把工具结果放进下一次请求。模型不会直接获得文件系统权限；知道文件名也不能跳过读取规则。这里的工具调用次数是 3，模型请求次数是 4，最后一次请求用于给用户答复。

本次没有发生分页或参数修正。分页、错误参数回传与权限拒绝的证据来自本地自检，不能把它们算作本次真实模型已经表现出来的能力。

## 业务判断：错误对象不等于 HTTP 404

模型正确指出：查询不到订单时，`ORDERS.get()` 返回 None，再读取 `order["total"]` 会出错。

它给出的示意修复包括返回 `{"error": "Order not found"}`，并提醒调用方处理成 404。后一半不能省略：现有 HTTP 包装代码在函数正常返回后会设置 `status = 200`。只照抄这个错误字典，接口可能从“500 报错”变成“200 携带错误信息”，仍不是完整的业务修复。

真正验收修复时至少检查：不存在的订单返回 404；已存在的订单仍返回 200 和正确金额。本轮只读排查，没有修改代码或执行这项修复。这个业务规则是下一步讨论的对象。
