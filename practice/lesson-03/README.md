# 第 3 课实践：沿着一次 500 找到证据

先读[第 3 课：工具调用循环](../../chapters/03-工具调用循环.md)。本课只要求解释一次完整调用过程；完整实现已提供。

## 必做：运行，再改一个输入

在仓库根目录运行：

```bash
python -B practice/lesson-03/demo.py
python -B practice/lesson-03/demo.py --order-id order_001
```

第一次请求缺失订单 `order_404`：HTTP 返回 500，程序读日志、读源码，再给出诊断。第二次请求已有订单 `order_001`：HTTP 返回 200，只读取日志，说明本次没有复现 500。

![500 报警后，从日志和代码中取证据。](../../assets/tool-calling-loop-illustrations/01-evidence.png)

先预测第二条命令会少调用哪个工具，再运行核对。已有订单成功不代表缺失订单的缺陷被修复。

## 代码只看这些位置

- [demo.py](demo.py) 的 `TOOLS`：模型能申请什么。
- 同文件的 `execute_read()`：检查参数与允许名单，再真正读取文件。
- 正文的 `run_loop()`：把结果连同调用编号交回模型，继续或停止。

演示复用[综合项目](../workspace-agent/README.md)的完成版循环，不要求先阅读整个实现。`order_service.py` 故意保留缺失订单错误；不要为了让实验变绿而直接修掉它。

## 完成标准

能根据终端输出指出：模型什么时候申请了读取，程序什么时候真正读取，证据怎样进入下一次请求，以及为什么两种订单走了不同路径。

```bash
python -B practice/lesson-03/check.py
```

检查覆盖真实 HTTP 500/200、消息配对、批量工具错误、截断与预算停止。服务、文件和日志真实运行；模型回复是预设分支，检查通过不证明真实模型有通用诊断能力。演示只监听本机，运行结束关闭服务；普通运行会保留临时证据目录，系统可能随后清理它。

## 选做：目录查看与真实模型

[multiply.py](multiply.py)是独立的乘法协议示例，仅在想排除文件与 HTTP 细节时阅读；无需再完成一遍才进入下一课。无参数运行也是离线自检；只有 `python -B practice/lesson-03/multiply.py --live` 才连接真实模型，最多 8 次请求，客户端超时 30 秒、SDK 自动重试 0。
