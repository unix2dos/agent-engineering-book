# 第 14 课实践：限制资源并如实收尾

正文见[第 14 课：Agent 运行控制](../../chapters/14-Agent运行控制.md)。本课只有这个实践入口，实现复用[现有配置工作流](../lesson-10/workflow_demo.py)，不另建 Agent 或复制执行脚本。

前置是理解第 3 课工具循环，以及第 9、10 课的程序验收与修复流程。RAG、MCP 不是本课必修前置。默认使用固定剧本模型；文件读写、工具账本、Agent Loop 和评分器都真实运行，无需密钥或付费请求。

## 1. 先预测，再看执行结果

任务要求把主题改为 dark，端口保持 3000。固定剧本第一轮写成 dark / 8080，第二轮尝试修复。先预测两组限制的结果，再运行下面两个小节的命令。不要清空函数，不要求重写 Python 脚手架。

## 2. 整个任务共用工具执行次数

```bash
python -B practice/lesson-10/workflow_demo.py --tool-budget 3
```

读取和写入各消耗一次额度，跨修改轮次共享。第一轮读取、写入消耗两次；第二轮读取用掉最后一次，随后修复端口的写入被拒绝。文件仍是 `theme=dark`、`port=8080`，验收为 `failed`，工作流结果为 `tool_budget_exhausted`，退出码为 **2**。

程序在工具参数校验通过后、实际执行前扣减并保存额度；进入工具执行入口后的失败也不退回额度。参数不合法或预算耗尽的调用不会执行，仍按原调用编号返回拒绝回执。每轮报告会记录 `remaining_tool_calls`。

把额度改为 `--tool-budget 4`，固定剧本会完成第二轮修复，余额恰好为零仍可验收通过。省略此参数时保持原有行为，不单独限制工具次数。

拒绝回执进入现有 Agent Loop 后，后续模型请求仍受原有预算和每轮上限控制。程序在本轮结束后验收文件，预算不足时不再启动下一轮修复。这里未实现并发扣减或自动恢复。

## 3. 在总预算内预留一次收尾请求

```bash
python -B practice/lesson-10/workflow_demo.py --model-budget 5 --reserve-summary
```

前四次请求用于推进任务；执行阶段停止后，程序先验收当前文件，再用第五次请求根据验收结果总结。该请求不提供工具，也不进入工具执行循环。即使模型仍返回工具调用，程序也不会执行，而会用固定文字报告停止原因。

收尾输入还包含原始任务、初始配置、会话中已有的调用与回执，以及分开记录的模型请求额度和工具执行额度。缺少回执的动作标为结果未知，不推断为未执行。实际输入保存到报告的 `summary_evidence`，便于核对模型是否误解了停止原因。

程序生成的 `status_report` 单独报告任务状态、产物评分、两类额度和是否取得原 Agent 的最终回答。模型文字放在“模型说明”下，不改变这些字段。`summary_status=completed` 只表示非空文本正常返回且没有工具调用，不证明说明在语义上准确。

预留收尾请求会减少推进任务的次数。在固定剧本中，总预算为 5 且不预留时，第二轮写入已经完成，文件通过验收，但拿不到最后的回答；预留一次后，第二轮只来得及读取，端口仍为 8080，文件验收失败。任务状态仍为 `model_budget_exhausted`，`summary_status=completed` 只表示收尾请求完成。

总结超时或返回不合法内容时，程序保留停止原因与验收结果，不增加预算重试；一次失败的总结同样消耗请求次数。正常完成的任务不额外请求总结。默认模型的总结也是固定剧本，本实验验证控制路径，不验证真实模型的总结质量；也未加入总截止时间或费用额度。

## 4. 完成标准

根据运行目录里的 `workspace/config.json`、`report.json` 和 `session.jsonl`，完成一份自己的判断：

- 工具额度为 3 时，指出被拒绝的调用，确认端口仍为 8080，拒绝回执关联原来的调用编号。
- 将工具额度改为 4，解释为什么余额为零但任务仍可完成。
- 模型额度同为 5 时，对比预留与不预留总结的结果，分别说明文件是否合格、运行是否完成。
- 解释并发名额何时归还，以及排队后为什么要重新计算剩余时间。后两项是场景判断，不声称本工作流已经实现并发调度和总截止时间。

这里的完成标准是学习目标；检查脚本通过不能代替读者自己的解释。`summary_status=completed` 只表示收尾请求正常结束，不能覆盖任务的失败或预算停止状态。

## 5. 验证范围

运行已有工作流自检即可，不需要新建第二份测试：

```bash
python -B practice/lesson-10/workflow_demo.py --self-check
```

检查覆盖工具额度跨轮共享、同批调用逐个检查、拒绝回执配对、余额恰好用完、预留总结、总结超时不重试，以及收尾模型即使申请工具也不执行。实测读回被拒绝的轨迹还验证：总结输入包含原任务、动作与两类额度，模型误报成功不能覆盖程序报告。全书离线入口已经通过第 10 课检查调用这个自检。
