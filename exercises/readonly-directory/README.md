# 小需求：让排查助手先看看有哪些文件

助手现在只知道两个固定文件名。增加一个 `list_files` 工具，让它先取得目录清单，再申请读取已有权限范围内的文件。

这次只写 [starter.py](starter.py) 中的 `list_files()`。工具说明、参数检查、结果回传和测试已经准备好；第一遍不用读完验收代码。

## 需求与验收

输入是工作区 `workspace` 和相对目录 `path`，默认 `"."` 表示工作区本身。返回示例：

```python
{"path": ".", "files": ["order_service.py", "server.log"]}
```

- 只列当前目录的普通文件，按文件名字典序排序；不递归，不读取文件内容。
- 返回原来的相对 `path` 和文件名，不返回绝对路径。子目录中的结果仍是文件名，例如 `worker.log`。
- 目录里的软链接全部跳过，包括指向工作区内部的链接和失效链接。子目录本身不加入文件清单。
- 绝对路径、越界路径、指向外部目录的软链接、非目录或不存在的目标，都抛出 `ValueError`。
- `path` 不是字符串或是空字符串，也抛出 `ValueError`。空目录正常返回 `files=[]`。
- 不修改任何文件。获得目录清单，不代表获得其中所有文件的读取权限。

已有 `resolve_workspace_file(workspace, path)` 可复用，它会解析真实路径并拒绝绝对路径和越界。你需要补上输入检查、目录判断和文件筛选。这里处理受控的小目录，暂不做递归和分页，也不把静态路径检查当作完整操作系统沙盒。

## 开始做

在仓库根目录运行：

```bash
python -B exercises/readonly-directory/check.py
```

现在会报 `NotImplementedError: 请实现 list_files`，因为核心函数留给你写。填好后，仍用同一条命令验收。

完成时会验证三个真实目录：工作区、`logs` 子目录和空目录；再检查越界及软链接，最后复用现有 Agent Loop 走完 `list_files -> read_file -> Final`。所有文件由测试临时创建，结束后清理，无需 Key。

预设模型只用来验证接线，不代表真实模型已能自行选择文件。`--wiring` 使用固定目录结果，仅供检查已提供的接线代码；它通过不算你的作业通过。
