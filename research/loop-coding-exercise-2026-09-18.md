## 先看发生了什么

## 读过的文件，为什么还要核对指纹

模型收到代码后，还需要一段时间才提出修改。这期间文件可能被别人更新。直接覆盖会把新内容抹掉，即使模型的修改本身没有语法错误。

本次采用：`读取内容与指纹 → 模型提出新内容和旧指纹 → Harness 重新读取当前文件并比较 → 一致才写入`。不一致返回 `file_changed`，文件保持原样，模型必须重新读取。作者明确表示理解这个机制，并认可按此实现。

这里包含两个不同的保护：指纹比较发现“读到的版本已经过时”；先写临时文件、完成后重命名替换，避免中途留下只写了一半的目标文件。

它还不是任意编辑器之间的原子并发控制。检查和替换之间仍有时间窗口；当前成立的前提是独立练习目录、一个活跃任务、不同时手工编辑。接入真实共享仓库时，需要进一步协调所有写入者或使用不可变快照。

## 测试失败，为什么不立即结束 Agent

工具执行和任务成功是两层判断。测试进程正常执行完毕，仍可能返回非零退出码；这个输出正是模型修复问题所需的信息。

`RunExerciseTests` 保存真实 stdout、stderr 和容器退出码，将非零退出码作为 `command_failed` 回执交回原循环。下一次模型请求读到回执，才决定如何修改。若容器是否结束或清理是否完成无法确认，则返回运行错误并停止，不当作普通测试失败继续。

因此，这条轨迹里的“一次工具错误”与最终现有测试通过并不矛盾。`status=completed` 只说明模型循环结束，通用任务结果仍是 `not_evaluated`；本次修复的结论另外来自真实测试与文件核验。六个既有用例通过，不是对所有输入的数学证明。

## 限制路径，为什么还要限制执行环境

`go test` 会运行项目代码。即使命令文本固定，也不能把测试当成无副作用的读取工具。

本次文件读写由本机 Harness 执行，仅限四份指定文件、只允许修改 average.go；测试进程才在容器内运行。容器仅挂载这个练习目录，且只读，没有本机其他仓库、Docker socket 或模型密钥。它使用非 root 用户、断网、只读根文件系统和资源限制。新会话的一次授权不会扩大普通对话的只读工具集，公共部署模式拒绝练习及其追问。

隔离检查曾发现一个配置错误：临时目录禁止执行，Go 编译出的测试二进制因此报 `permission denied`，尚未触及练习本身的 bug。修正为只让容器的临时编译目录可执行，项目仍只读；随后才验证预期的除零失败与修复成功。这个过程说明：先确认工具运行环境可用，才有资格把失败归因于目标代码。

## 已完成的验证与下一条学习线索

- 离线检查：过期指纹拒绝写入、成功修改证据、保护文件/路径/参数、输出截断、缺少授权及公共模式拒绝。
- 真实 Docker 检查：原始测试失败、修复后通过；非 root、无法改写项目或根目录、无模型密钥/套接字、无法外连；取消后清理容器。
- HTTP 检查：Coding 工具不会污染普通模式，追问沿用授权练习，父轮原始记录保持不变。
- Go race 检查、19 项轨迹/用量检查与 4 项 Python 参考行为契约通过。实际网页已核对授权入口、原始记录默认页、diff、测试输出与图标。
